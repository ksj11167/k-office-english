# K-직장인 영어 — PRD

v1 출시 범위를 자르기 위한 문서. 무엇을 만드는지보다 **무엇을 안 만드는지**가
핵심이다. 설계 근거는 `decisions.md`(D1~D17)에 있고, 여기서는 반복하지 않는다.

- 작성 시점: 프로토타입 동작 확인 후 (`app/` 배포 가능 상태)
- 상태: **v1 범위 확정.** 출시 일정 제약 없음 (2026-09-15 확인)

---

## 1. 누구를 위한 앱인가

**한국에서 일하는 직장인 중, 영어로 일해야 하는 순간이 가끔 오는 사람.**

- 토익 점수는 있는데 막상 슬랙/미팅에서 한 줄이 안 나오는 사람
- 유학·어학연수 경험이 없고, 학원 다닐 시간도 없는 사람
- "확인하고 말씀드릴게요"를 영어로 어떻게 하는지 매번 검색하는 사람

**대상이 아닌 사람**: 영어 초보(기초 문법이 필요한 사람), 시험 준비생,
영어가 모국어에 가까운 사람.

## 2. 왜 기존 앱으로는 안 되나

| | 문제 |
|---|---|
| 듀오링고 | 게임은 재밌는데 "사과 먹는다"를 배운다. 회사에서 쓸 일이 없다 |
| 스픽 | 말하기 중심은 맞는데 교재가 일반 회화다. 내 상황이 아니다 |
| 번역기 | 그때그때 해결되지만 **남지 않는다**. 같은 문장을 매번 다시 찾는다 |

빈 곳: **한국 직장인이 실제로 쓰는 한국어 표현 → 그 상황의 자연스러운 영어**,
그리고 그게 **입에서 나올 때까지** 반복.

## 3. 핵심 가설

> 사람은 "상황"에 막혀서 말을 못 한다. 직무가 아니라.
> 그런데 같은 상황이라도 **쓰는 단어는 직무마다 다르다.**

측정으로 확인함 (`app/js/job-decks.js` 60장 기준):

- 세밀한 상황 태그 57종 중 직무 간 겹침은 3종뿐
- 굵게 묶으면(보고·일정·요청·거절) 상위 4묶음이 **5개 직무 전부**에 걸침

→ **상황은 세로축, 표현은 가로축.** 둘 중 하나로 통합되지 않는다.
→ v1은 직무로 진입한다. 상황은 카드 태그로만 존재하고, 덱이 200장을 넘으면
   그때 필터 축으로 승격한다.

## 4. v1 범위

### 들어가는 것

| 기능 | 상태 |
|---|---|
| 직무별 표현 덱 (공통·개발·영업·기획PM·디자인) | 동작함, **직무당 40장 / 총 200장** |
| 스와이프 채점 (오른쪽 외움 / 왼쪽 다시) | 동작함 |
| FSRS 간격 반복 | 동작함 |
| 음성으로 말하고 채점 | 동작함, 기기 지원 시 |
| 완전 오프라인 | 동작함 |
| 진도 저장 (기기 내) | 동작함 |
| 첫 실행 온보딩 (직무 한 번 고르기) | 동작함 |
| **내 카톡 대화 가져오기** | 파싱·날짜분할·번역 전부 동작함. **번역 서버 필요** |
| 번역 프록시 서버 | **미착수** — v1의 유일한 새 백엔드 |

### 빼는 것 — 그리고 이유

| 뺀 기능 | 이유 |
|---|---|
| 사용자 기여 덱 | 백엔드 필요. 사용자가 없는데 서버부터 세우면 비용과 개인정보 책임만 먼저 생긴다 (D17) |
| AI 롤플레이 | 구현 난이도가 나머지 전부를 합친 것보다 크다 (D10) |
| 기기 간 동기화 | 계정 필요. v1은 기기 하나로 충분하다 |
| 알림·리마인더 | 습관이 붙는지 먼저 보고 나서 |

### 카톡 기능의 위치

한때 v1에서 뺐다가 되돌렸다. 뺀 이유는 두 가지였는데 하나만 유효한 것으로 드러났다:

- ~~"서버를 세울 시간이 없다"~~ → 출시 일정 제약이 없어지면서 무효
- **"첫 사용자에게 무거운 플로우를 먼저 보여주면 이탈한다"** → 여전히 유효

그래서 **기능은 넣되 기본 진입점으로 두지 않는다.** 홈은 직무 덱이고, 카톡은
"더 개인화하기"로 한 단계 안쪽이다. 습관이 붙은 뒤에 만나는 게 맞다.

### 번역 서버 — v1의 유일한 백엔드

카톡 기능이 v1에 있으려면 사용자가 API 키를 넣지 않아도 번역이 돼야 한다.
필요한 것은 프록시 하나뿐이다: 클라이언트 요청을 받아 서버가 보관한 키로
Anthropic에 중계. 로직은 작지만 **책임이 따라온다** — 비용 상한, 남용 방지,
요청 로그를 남기지 않는 것(대화 문장이 지나간다).

세션당 ~$0.01. 사용자 100명이 주 3회 쓰면 월 ~$12 수준.

### v1 출시 전 반드시 해야 하는 일

우선순위 순. **0번이 1번보다 먼저다.**

0. **본인이 2주 써보기** — 아무도 이 앱을 실제로 써본 적이 없다. `decisions.md`의
   "미해결" 표에 있는 값들(스와이프 140px, 음성 채점 70%, 세션 분량)은 전부 내가
   임의로 정한 것이다. 학습 루프 자체가 별로면 덱 200장은 헛수고가 된다
1. **번역 서버** — 카톡 기능을 일반 사용자에게 여는 유일한 열쇠 · **미착수**
2. ~~**덱 분량** — 직무당 40장, 총 200장~~ **완료.** 테스트가 40장 바닥을 지킨다
3. ~~**Android 빌드 검증**~~ **완료.** CI가 푸시마다 디버그 APK를 만든다
   (`setup-android`의 기본 패키지 목록에 폐기된 `tools`가 있어 패키지를 명시해야 했다).
   **iOS는 검증 중**
4. ~~**온보딩**~~ **완료.** 첫 실행이 직무를 한 번 묻고 바로 덱으로 들어간다
5. **스토어 자산** — 아이콘(있음), 스크린샷, 설명, 개인정보 처리방침

## 5. 성공을 어떻게 아는가

v1에서 답을 얻고 싶은 질문은 **"사람들이 다시 오는가"** 하나다.

| 지표 | 최소선 | 어떻게 재나 |
|---|---|---|
| D1 재방문 | 40% | 스토어 콘솔 |
| D7 재방문 | 20% | 스토어 콘솔 |
| 첫 세션 완주율 | 60% | 덱을 끝까지 넘긴 비율 |
| 세션당 카드 수 | 15장 이상 | — |

**측정하지 않는 것**: 학습 효과. "실제로 입에서 나오는가"(D4)는 v1에서 잴 방법이
없다. 재방문이 대리 지표다.

⚠️ v1에는 분석 도구가 전혀 없다. 스토어 콘솔 기본 지표 외에는 아무것도 안 보인다.
세션 지표까지 보려면 분석 SDK를 붙여야 하고, 그러면 개인정보 처리방침이 달라진다.

## 6. 열린 결정

| 질문 | 기본값 | 정해야 할 시점 |
|---|---|---|
| 앱 내 분석 도구를 넣나 | 안 넣음 | 스토어 제출 전 |
| 번역 서버를 어디에 올리나 | Cloudflare Workers | 서버 착수 시점 |
| 번역 무료 한도를 두나 | 일 N회 제한 | 서버 착수 시점 |
| 가격 | 무료 | v1은 무료 확정, 과금은 v2 이후 |
| 덱 200장을 누가 쓰나 | LLM 초안 + 사람 검수 | 지금 |
| iOS를 v1에 포함하나 | 포함 | Mac/CI 확보 여부에 달림 |

## 7. 비범위 — 하지 않기로 한 것

이건 "나중에"가 아니라 **하지 않는다**는 뜻이다.

- **카톡 대화 자동 수집** — 공식 API로 불가능하고, 알림 접근·접근성 서비스·로컬 DB는
  전부 스토어 정책 위반 또는 동의 없는 제3자 정보 수집이다 (decisions.md 배제 목록)
- **대화 로그 공유** — 공유 단위는 카드다. 원문은 절대 서버로 가지 않는다 (D16)
- **일반 영어 회화** — 직장 맥락을 벗어나면 이 앱이 이길 이유가 없다
