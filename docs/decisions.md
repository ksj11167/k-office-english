# K-직장인 영어 — 결정 기록

메신저 대화 로그를 학습 소스로 삼는 영어 말하기 앱. 이 문서는 `/deep-interview`
9라운드와 그 뒤 사용자 지시로 확정된 내용을 담는다.

- 인터뷰 종료 시점 모호도: **23.5%** (목표 10% 미달). 이후 D18~D25로 상당수가
  정해졌고, 남은 것은 아래 "미해결" 표에 있다 — 대부분 **실사용 없이는 못 정하는 값**이다
- 상태: **공개 배포 중** · 테스트 75개 · Android·iOS 빌드 CI 통과
- 앱: `app/` · 소개: `site/` · 백엔드: `server/`(번역 프록시, 코드 완료·미배포)
- 배포: GitHub Pages · Claude 아티팩트 · Capacitor(Android 먼저, iOS는 D21)

| D28 | **어느 메신저든** 가져온다: 붙여넣기 · 캡처 · 카톡 파일 | 테스터 피드백 — 회사에서는 텔레그램, 슬랙, 팀즈, 사내 메신저를 쓰는 사람이 많은데 내보내기 파일은 카톡에만 있다. 그래서 가져오기의 정문을 「붙여넣기」로 바꿨다. 메신저마다 문법을 쓰지 않고, 모두가 결국 귀결되는 두 모양만 읽는다: 한 줄에 「이름: 말」(inline), 이름·시간 머리줄 아래 말(blocks; 슬랙·팀즈·잔디·텔레그램 데스크톱, 이름과 시간이 두 줄로 나뉜 꼴 포함). 어느 쪽도 아니면(폰에서 말풍선만 복사) 모델이 읽는다. 폰은 드래그 복사가 안 되는 메신저가 많아 **캡처**를 받는다 — 아래 「배제한 것」의 캡처+OCR을 뒤집었다. 그때의 이유(발화자 부정확)는 글자만 뽑는 OCR 얘기였고, 비전 모델은 말풍선이 오른쪽이면 내 말이라는 걸 안다. 그래서 캡처로 가져온 대화는 「어느 쪽이 나인가요?」를 묻지 않는다. 긴 스크롤 캡처는 폰 화면 크기로 겹쳐 잘라 보낸다. 날짜가 없는 붙여넣기·캡처는 오늘 대화로 둔다. 가져온 대화는 **세션으로 따로 쌓는다**: 카톡 파일은 방 전체 기록이라 다시 가져오면 그 방 날짜들을 갈아끼우지만(D14 그대로), 붙여넣기·캡처는 대화 한 조각이라 옆에 추가한다. 「나」도 대화마다 따로 기억한다(카톡의 김세진, 슬랙의 Sejin Kim, 캡처의 나). 캡처는 번역 서버나 본인 API 키가 있어야 하고, 이미지는 서버에 저장하지 않는다 |
| D27 | 디자인 콘셉트는 **결재 서류** | 흰 바탕·파란 버튼·둥근 말풍선은 스픽·토스 같은 학습앱의 평균값이라 AI가 만든 것처럼, 스픽과 비슷하게 보였다. 차별점은 학습앱이 아니라 직장인의 하루에서 가져오기로 하고 두 시안(출근길 노선도, 결재 서류) 중 결재 서류를 골랐다. 카드는 사내 문서 양식(건명·받은 말·내 답), 채점은 「결재/반려」 도장(처음엔 「통과」였다가 실제 결재 용어인 「결재」로 바꿈), 완료는 결재란, 내 말은 형광펜. 인주 빨강은 도장과 결재·반려에만 쓴다. 이후 "좀 더 모던하게" 요청으로 인쇄 양식이 아니라 요즘 전자결재 앱처럼 다듬었다: 명조 대신 굵은 고딕 제목, 굵은 남색 테두리 대신 1px 연한 선, 12–16px 모서리, 연회색 책상 위 흰 문서. 말하기 버튼은 회사 말로 「보고」 |

## 미해결 (모호도 23.5%가 남은 이유)

10% 목표를 채우려면 Constraints·Criteria가 전 컴포넌트에서 0.90이어야 한다.
사용자가 취침 전 "프로토타입까지" 지시하여 아래는 **내가 가정으로 채웠다.**

| 항목 | 가정한 값 | 확인 필요 |
|---|---|---|
| 플랫폼 | 웹앱(PWA) + Capacitor | 해결 — 양쪽 네이티브 빌드가 CI에서 통과 (2026-09-16) |
| 오프라인 동작 | 번역만 온라인, 복습은 오프라인 | 미논의 |
| 기기 간 동기화 | 없음 (localStorage, 브라우저별) | 미논의 — `db` 도입 시 해결 |
| 음성 채점 임계값 | 토큰 일치 70% | 임의값. 실사용 튜닝 필요 |
| 스와이프 확정 거리 | 140px 또는 빠른 플릭 | 임의값. 손 크기·기기별 튜닝 여지 |
| 하루 세션 분량 | 그 날 전부 + 이전 날짜 복습 최대 8장 | 임의값 |
| 번역 모델 | `modelTier: "default"` | quick으로 낮출 여지 |

### 알려진 리스크

- **iOS Safari PWA는 공유 대상 등록 불가** → 카톡에서 바로 앱으로 못 보냄
- **Chrome 음성인식은 오디오를 구글 클라우드로 전송** → D7 완화 전의 온디바이스 원칙과 긴장. 현재는 상대방 발화도 보내기로 했으므로 일관성 문제는 줄었으나, 음성은 여전히 제3자 경유
- **카톡 내보내기 포맷은 고정 계약이 아님** — 카톡 업데이트로 깨질 수 있음. 파서 테스트가 회귀 방어선
- **다른 메신저의 복사 형식은 더더욱 계약이 아님** — 일반 파서(inline·blocks)는 추측이다. 미리보기 화면이 잘못 읽은 걸 잡는 마지막 방어선이고, 못 읽으면 모델이 읽는다
- **캡처 읽기는 모델 품질에 달림** — 작은 글씨, 겹친 캡처, 이름이 안 보이는 단체방에서 발화자를 틀릴 수 있다. 미리보기에서 확인
- `developers.kakao.com` 접근이 막혀 **카카오 API 제약을 공식 문서로 최종 확인하지 못함**
